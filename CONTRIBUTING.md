# Contributing Guide

This document summarizes the repository structure, build, tests, and code conventions for developers.  
For library usage, see [README.md](README.md) and [docs/reference.md](docs/reference.md).

---

## Repository Structure

This is a Maven multi-module project.

| Module | Target | Compile |
|---|---|---|
| `pxl-javax` | Java 8+, `javax.*` | source/target 8 |
| `pxl-jakarta` | Java 17+, `jakarta.*` | source/target 17 |

> ⚠️ The source lives only in `pxl-javax`. Do not edit `pxl-jakarta` directly.

`pxl-jakarta` contains no hand-written source.
At build time it is generated by file-system-copying the source tree of the sibling module `pxl-javax` (`src/main/java` and `src/main/resources`, and `src/test` for tests), applying the string substitutions below, and then compiling (via the `maven-antrun-plugin` in `pxl-jakarta/pom.xml`).

```
import javax.annotation.   →   import jakarta.annotation.
import javax.validation.   →   import jakarta.validation.
```

Therefore:

- Always make code changes in `pxl-javax`. To change `pxl-jakarta` behavior, fix `pxl-javax` and rebuild.
- Restrict `pxl-javax`'s portable imports to exactly `javax.annotation.*` / `javax.validation.*` — any other `javax.*` (e.g. `javax.imageio`) is not substituted and remains as-is in the jakarta variant.

The base package is `io.github.hclimkr.pxl`, and the boundary between the public API (`Pxl`, `annotation`, `option`, `exception`, `styler`, `util`, `constraint`, `builder`) and the internal implementation (`internal/*`) is maintained by the `.internal.` naming convention (users do not reference `internal.*`).

## Development Environment

- JDK 17 must be on the PATH (`pxl-javax` compiles to 8, but the build itself runs on JDK 17).
- Lombok is used throughout and is wired as an annotation processor in each module's `maven-compiler-plugin`. Enable the Lombok plugin in your IDE.

## Build & Test

`pxl-jakarta` copies `pxl-javax`'s source tree directly, so it does not depend on artifact install (the reactor order is preserved by the declaration order in the root `<modules>`),
but to build both modules at once it is recommended to run from the root.

```bash
mvn clean install                                    # Build both modules + tests
mvn -pl pxl-javax test                               # javax module tests (all logic lives here)
mvn -pl pxl-javax test -Dtest=PxlExcelExportTests    # Single test class
mvn -pl pxl-javax test -Dtest=PxlExcelImportTests#someMethod   # Single test method
mvn clean install -DexcludedGroups=network           # Exclude network-dependent tests
mvn install -DskipTests                              # Build without tests
```

- Tests are based on JUnit 5 (Jupiter) + AssertJ.
- Tests that access external images (picsum.photos) are `@Tag("network")` and can be excluded with `-DexcludedGroups=network`.
- Export result files are written to `pxl-javax/target/test-outputs/*.xlsx` (and `*.xls`) (`TestPaths.EXPORT_DIR`); since they are under `target/`, they are deleted by `mvn clean`.

## Test Writing Conventions

- Do not create new `*Tests.java`. The runnable classes are organized by feature category in the root test package `io.github.hclimkr.pxl` (`PxlRoundTripTests`, `PxlTypeConversionTests`, `PxlExcelImportTests`, `PxlExcelExportTests`, `PxlCsvImportTests`, `PxlNameMatchingTests`, `Pxl{Column,Sheet,Workbook}OptionTests`, `PxlStyleTests`, `PxlSampleExcelExportTests`, `PxlI18nTests`, `PxlExceptionTests`, `PxlRegressionTests`, `Pxl{Picture,PictureNetwork}ExportTests`, `PxlLargeDataTests`, `PxlUtilityTests`), so add methods to the relevant feature class.
- Naming convention: class name = feature category, method name = `feature_situation_result` camelCase (e.g. `importExcel_mergedRegion_streaming_throws`).
- Annotated DTO fixtures that are binding targets go under the `tcdata/` subpackage. Input data is mostly created directly in code within each test.
- Add regression/characterization tests together with any change that alters logic or performance.

## Code Conventions

- Write JavaDoc (`/** */`) and inline/block comments (`//`, `/* */`) in English.  
  Exception/diagnostic messages, however, are keyed into the i18n bundle (`pxl-messages{,_ko}.properties`, base = English) and resolved via `PxlI18nDiagnostic.get(...)`.
- Validate required arguments of the public API with imperative `PxlAssertSupport` calls (`notNull`/`notEmpty`/`notBlank`), not with parameter annotations.  
  Use the internal `@Nullable` (`internal/constraint`) for nullability markers.
- To add support for a new field type, add a codec class under `internal/codec/` and add a branch in all three methods of `PxlCellResolver` (`parseDataValueFromCell`, `parseDataValueFromString`, `buildDataCell`).
- The working tree uses CRLF, but there is no `.gitattributes`; with `core.autocrlf=true` (this repo's setup) Git normalizes the committed blobs to LF. Take care not to mix EOLs after bulk substitutions.

## Pull Request

1. Branch off `main`.
2. Add/modify tests corresponding to the change.
3. Verify locally that `mvn clean install -DexcludedGroups=network` passes.
4. Open the PR.
