# PXL 0.9.1

Exception-contract release for **PXL** — every failure that crosses the public API now arrives as a concrete `PxlException` subtype you can catch on its own.

Pre-1.0 release: carries one source-breaking change (`PxlException` is now `abstract`), as the API stays open to refinement before `1.0.0`.

## Highlights

  - **Breaking**: `PxlException` is `abstract` — `new PxlException(...)` no longer compiles; catching it and declaring `throws PxlException` are unaffected
  - **`PxlSystemException`**: the subtype wrapping failures PXL does not classify — a checked I/O failure, an unexpected runtime failure from POI — with the original kept in `getCause()`
  - **`PxlIOException`** for a failed Excel open: a missing file, an unreadable or password-protected container, an unsupported format
  - **Import builders**: `override(...)` and `workbookName(...)` may now also be chained after `workbook(...)`/`sheet(...)`, matching the export builders; the value set last wins
