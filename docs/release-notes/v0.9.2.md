# PXL 0.9.2

Housekeeping release for **PXL** — every builder `sheet(...)` overload now leads with `rowClass`, the two static lookups that lived on `Pxl` move next to the types they answer about, a new lookup names the format of an already open POI workbook, and an Excel import from a file names the workbook after the file.

Pre-1.0 release: carries source-breaking signature changes with no behavior change, as the API stays open to refinement before `1.0.0`.

## Highlights

  - **Breaking**: every `sheet(...)` overload takes `rowClass` first, then the collection, then the sheet name — `exportExcel().sheet(Employee.class, employees, "Employees")`, `exportSampleExcel().sheet(Employee.class, "Employees")`, `importExcel().sheet(Employee.class, Set.class, "Employees")`, `importCsv().sheet(Employee.class, Set.class)`. A given position now always carries the same meaning across the builders; the import overloads that already led with `rowClass` are untouched
  - **`@PxlWorkbookName` file-name fallback**: `importExcel().workbook(W.class).fromFile(file)` binds the file name without its extension (`Report.xlsx` → `"Report"`) when `workbookName(...)` was not set; an explicit name still wins, and a stream source leaves the field `null`
  - **Breaking**: `Pxl.getWorkbookFileFormatFromWorkbookObject(Class)` is now `PxlFileFormat.fromWorkbookObject(Class)` — the same lookup, on the type it returns
  - **Breaking**: `Pxl.getWorkbookNameFromWorkbookObject(Object)` is now `PxlWorkbookUtils.getWorkbookNameFromWorkbookObject(Object)`, beside the other workbook helpers
  - **`PxlFileFormat.fromPoiWorkbook(Workbook)`**: names the format of an already open POI workbook — `HSSFWorkbook`→`HSSF`, `SXSSFWorkbook`→`SXSSF`, and both `XSSFWorkbook` and the streaming reader's `StreamingWorkbook`→`XSSF`
