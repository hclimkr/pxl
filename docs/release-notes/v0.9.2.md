# PXL 0.9.2

Housekeeping release for **PXL** — the two static lookups that lived on `Pxl` move next to the types they answer about, a new lookup names the format of an already open POI workbook, and an Excel import from a file names the workbook after the file.

Pre-1.0 release: carries two source-breaking moves with no behavior change, as the API stays open to refinement before `1.0.0`.

## Highlights

  - **`@PxlWorkbookName` file-name fallback**: `importExcel().workbook(W.class).fromFile(file)` binds the file name without its extension (`Report.xlsx` → `"Report"`) when `workbookName(...)` was not set; an explicit name still wins, and a stream source leaves the field `null`
  - **Breaking**: `Pxl.getWorkbookFileFormatFromWorkbookObject(Class)` is now `PxlFileFormat.fromWorkbookObject(Class)` — the same lookup, on the type it returns
  - **Breaking**: `Pxl.getWorkbookNameFromWorkbookObject(Object)` is now `PxlWorkbookUtils.getWorkbookNameFromWorkbookObject(Object)`, beside the other workbook helpers
  - **`PxlFileFormat.fromPoiWorkbook(Workbook)`**: names the format of an already open POI workbook — `HSSFWorkbook`→`HSSF`, `SXSSFWorkbook`→`SXSSF`, and both `XSSFWorkbook` and the streaming reader's `StreamingWorkbook`→`XSSF`
  - Both `PxlFileFormat` lookups throw nothing and never return `null`: a `null` argument or an unrecognized type falls back to `PxlConstants.DEFAULT_EXPORT_FILE_FORMAT` (`XSSF`)
