# PXL 0.9.3

API and behavior release for **PXL** — the export format attribute now names a POI engine instead of a file format, and a sheet name matches ignoring case everywhere a sheet is looked up: reading Excel and CSV, checking for duplicate sheets on export, and overriding a superclass sheet.

Pre-1.0 release with a **breaking API change**: `@PxlWorkbook(exportFileFormat)` becomes `@PxlWorkbook(exportExcelEngine)` and takes the new `PxlExcelEngine`, while `PxlFileFormat` keeps physical formats only. Migration is a rename plus an enum swap — see the first two highlights. Column headers are unaffected by the sheet-name change and stay case-sensitive.

## Highlights

  - **`exportExcelEngine` replaces `exportFileFormat`** *(breaking)*: the attribute — and `PxlExportWorkbookOption.exportFileFormat` with it — now takes a `PxlExcelEngine` (`HSSF` / `XSSF` / `SXSSF`), the POI implementation that writes the workbook. One enum used to answer two unrelated questions, which is what let a workbook declare `exportFileFormat = CSV` — a format no writer can produce — and fail at runtime with an unsupported-format `PxlDataException`. Naming a writer that cannot exist is now a compile error, so that check and its message are gone rather than reworded. To migrate, rename the attribute and swap the enum: `PxlFileFormat.SXSSF` → `PxlExcelEngine.SXSSF`
  - **`PxlFileFormat` names physical formats only** *(breaking)*: `XLS`, `XLSX` and `CSV` in place of `HSSF`, `XSSF`, `SXSSF` and `CSV`. `XSSF` and `SXSSF` had carried byte-identical extension, content type and limits all along — they are one format written two ways — and are now the single `XLSX`. What the enum keeps is what you read rather than declare: the filename extension and MIME content type for a download response, and the limits an export is bound by. `fromPoiWorkbook(...)` answers on this axis now, so a streaming-reader workbook reports `XLSX`; ask `PxlExcelEngine.fromPoiWorkbook(...)` when you need the writer
  - **Case-insensitive sheet matching on import**: `Employees.csv` binds a sheet declared as `@PxlSheet(name = "employees")`, and an Excel sheet named `EMPLOYEE` binds the alias `Employee` — a CSV sheet is named after its file, and a file name carries whatever casing the file system holds. Whitespace is still removed from both sides before comparing
  - **Case-insensitive duplicate check on export**: two sheets named `Employees` and `EMPLOYEES` are now rejected with `PxlDataException` naming both, before anything is written, instead of reaching POI as a `PxlSystemException` with sheets already created. No export that used to succeed fails now — a workbook could never hold both
  - **Case-insensitive superclass sheet override**: `importOverrideSuperClassSheet` / `exportOverrideSuperClassSheet` recognize a subclass `@PxlSheet(name = "EMPLOYEES")` as overriding a superclass sheet named `Employees`, since the two names denote one sheet
  - **Contributing policy**: `CONTRIBUTING.md` / `CONTRIBUTING_ko.md` state that the repository accepts issue reports and suggestions only — pull requests are not accepted, and the maintainer reviews each issue and makes the change
  - **Invalid date serials are reported**: a numeric cell whose serial number is no Excel date (a negative one, say) is rejected with a `PxlCellCodecException` naming the value, where a java.time column used to fail with a message-less `NullPointerException` and a `Date` column bound nothing at all
  - **Sample i18n reaches collections**: `exportSample` is translated on `Collection<String>` / `Collection<Enum>` columns as well, element by element and split by `exportCollectionSeparator`, where before only String and enum scalars were translated
  - **Translated dropdowns**: `exportOptionItems` on a `String` column is translated through the same bundle, so a sample cell no longer violates its own data validation; enum, numeric and temporal columns keep their items verbatim because they always write the canonical value

## Internal

  - **Export builder base split in two**: the format-neutral `PxlAbstractExportBuilder` keeps the option and the `toFile`/`toStream` terminals (resource handling, exception normalization) and delegates writing to three seams — `prepare()` before the destination is opened, `writeTo(OutputStream)`, `cleanup()` in the `finally` — while the new POI-only `PxlAbstractExcelExportBuilder` holds `toWorkbook()`, the creation result and the workbook implementation of those seams. Both are package-private and no public signature moved, so nothing changes for callers; the split is groundwork for a writer that is not a POI workbook
